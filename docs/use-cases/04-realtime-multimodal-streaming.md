# Guide 04: Real-Time Multimodal Streaming (Audio, Video & Voice AI)

## Problem & Architectural Challenge

Next-generation conversational AI assistants (e.g., GPT-4o Voice, Gemini Live, real-time avatar agents) process multiple high-velocity sensory modalities simultaneously within an interactive session:
- **Audio Ingestion**: Raw 16kHz PCM chunks arriving every 20ms from a microphone.
- **Vision Ingestion**: 1080p JPEG/RGB camera frames captured at 15–30 FPS.
- **LLM Token Stream**: Incremental text tokens generated by the core model.
- **TTS Synthesis**: Synthesized voice audio chunks sent to the speaker.

### The Interleaved Multi-Consumer Bottleneck
Different workers operate on different cadences:
- Voice Activity Detection (VAD) runs every 20ms to detect speech onset/offset.
- Whisper Speech-to-Text runs on complete audio phrases (every 500–1000ms).
- Vision Captioning (e.g. Moondream, MiniCPM-V) samples frames every 1000ms.
- Text-to-Speech (TTS) chunks words as tokens arrive.

Coordinating these in-process with raw `asyncio.Queue` leads to race conditions, dropped frames, and memory fragmentation.

## Architectural Flow

```
│                 Session Sensory Producers                   │
│   Microphone (PCM 20ms)      Camera (15 FPS RGB Frames)     │

               │                              │
               ▼                              ▼
        session/1/audio/in             session/1/video/in

                              ▼
               ┌──────────────────────────────┐
               │         apister Bus          │
               │  - Sub-millisecond latency   │
               │  - MQTT topic trie routing   │
               │  - Zero-copy binary payloads │
               └──────────────┬───────────────┘
                              │
        ┌─────────────────────┼─────────────────────┬─────────────────────┐
        ▼                     ▼                     ▼                     ▼
┌────────────────┐   ┌────────────────┐   ┌────────────────┐   ┌────────────────┐
│ VAD Worker     │   │ Whisper STT    │   │ Vision Worker  │   │ Video Archive  │
│ (20ms latency) │   │ (Chunks Audio) │   │ (Sampled 1 Hz) │   │ (Full 15 FPS)  │
└────────────────┘   └────────────────┘   └────────────────┘   └────────────────┘
```

---

## Topic Hierarchy Design

- `session/<session_id>/audio/in`: Inbound microphone PCM audio chunks.
- `session/<session_id>/video/in`: Inbound camera video frames.
- `session/<session_id>/stt/transcript`: Recognized text transcripts from speech.
- `session/<session_id>/llm/token`: Generated assistant text tokens.
- `session/<session_id>/audio/out`: Synthesized TTS audio chunks for speaker playback.

## Production Implementation

```python
import asyncio
from pathlib import Path
from apister import Bus, OverflowPolicy


async def mic_stream_producer(bus: Bus, session_id: str) -> None:
    """Publishes raw audio chunks every 20ms."""
    pcm_chunk = b"\x00\x02" * 320  # 640 bytes = 20ms of 16kHz 16-bit PCM
    for _ in range(50):
        await bus.publish(f"session/{session_id}/audio/in", pcm_chunk)
        await asyncio.sleep(0.02)


async def camera_stream_producer(bus: Bus, session_id: str) -> None:
    """Publishes video frames at 15 FPS."""
    frame_bytes = b"[RAW_JPEG_IMAGE_DATA]" * 5_000  # ~100 KB frame
    for _ in range(15):
        await bus.publish(f"session/{session_id}/video/in", frame_bytes)
        await asyncio.sleep(0.066)


async def vad_worker(bus: Bus, session_id: str) -> None:
    """Voice Activity Detector: ultra-low latency, drops old frames if lagged."""
    sub = await bus.subscribe(
        f"session/{session_id}/audio/in",
        queue_size=4,  # Tiny buffer: only needs the freshest 80ms of audio
    )
    async for envelope in sub:
        # VAD inference simulation (< 1ms)
        pass


async def vision_worker(bus: Bus, session_id: str) -> None:
    """Vision understanding: samples frames periodically."""
    sub = await bus.subscribe(
        f"session/{session_id}/video/in",
        queue_size=2,
    )
    async for envelope in sub:
        print(f"[Vision] Processing sampled frame (offset {envelope.offset})...")
        await asyncio.sleep(0.2)  # Model inference time (5 FPS max)


async def main() -> None:
    async with await Bus.open(
        "data/multimodal_bus",
        overflow=OverflowPolicy.DROP_OLDEST,  # Real-time sensor feeds drop stale frames
        tail_cache_bytes=32 * 1024 * 1024,
    ) as bus:
        session = "user_live_01"
        await asyncio.gather(
            mic_stream_producer(bus, session),
            camera_stream_producer(bus, session),
            vad_worker(bus, session),
            vision_worker(bus, session),
        )


if __name__ == "__main__":
    asyncio.run(main())
```

---

## Why `apister` Excels in Real-Time Multimodal Workflows

1. **Sub-Millisecond Tail Cache**: Audio and video chunks stay in RAM; real-time workers (VAD, Vision) access payloads with zero disk read overhead.
2. **Independent Buffer Sizing**: The VAD worker uses `queue_size=4` to strictly process live audio, while an archival recording worker can use `queue_size=1024` with `name="recorder"` to ensure not a single millisecond is missed.
